PART Ⅰ · PERFORMANCE ASSESSMENT

실습 과제(20%) 평가 운영 지침

매주 실습 과제의 수행 흐름, AI 활용 허용 범위와 위반 시 처리 방안, 평가요소·배점 및 4단계 채점기준.

적용 성취기준 [12자구01-01] ~ [12자구05-03] (단원1~5 전 범위 — 해당 주차 학습 내용에 대응하는 성취기준을 매주 누적 적용)

1수행 과제 흐름과제 공지 → 구현 계획 → 구현 → 검증·성찰 → 제출
01
과제 공지 및 요구사항 확인

수업 종료 시 이번 주 실습 주제(자료구조 구현 또는 응용)의 요구사항, 제출 형식(.py 코드 + 성찰일지), 제출 기한, 채점기준표를 함께 공지한다. 학생은 요구사항에서 애매한 부분을 질의응답으로 명확히 한다.

02
구현 계획 수립

코드 작성 전 어떤 자료구조와 연산을 사용할지, 목표로 하는 시간·공간 복잡도를 먼저 정리한다. 복잡도 목표 없이 바로 구현에 들어가는 것을 금지한다.

03
구현 (개별 코드 작성)

확정된 계획에 따라 파이썬 코드를 작성한다. 진행 중 막히는 지점에서 AI 활용 허용범위 내에서 도움을 받을 수 있으며, 활용 내역을 즉시 메모해 둔다.

04
자체 검증 및 성찰일지 작성

직접 실행 결과를 확인하고(가능하면 간단한 테스트 케이스 포함), 선택한 자료구조·복잡도의 근거·어려웠던 점·AI 활용 내역을 성찰일지에 기록한다.

05
제출 및 피드백 회수

코드와 성찰일지(AI 활용 신고 포함)를 함께 제출한다. 채점기준표 기반 피드백을 받고, 재제출이 허용된 과제는 안내된 기한 내 보완한다.

2AI 활용 허용 범위허용 · 조건부 허용 · 금지 3단계

과제 수행 과정에서 AI 도구(챗봇 등) 활용 여부 자체를 금지하지 않는다. 다만 ‘학습을 보조하는 도구’와 ‘과제를 대신 수행하는 대필자’의 경계를 아래와 같이 명확히 구분한다.

허용

학습을 보조하는 용도로 자유롭게 활용 가능. 활용 사실을 성찰일지에 간단히 기록한다.

  • 개념 질의 — “스택과 큐의 차이가 뭐야?”
  • 문법·에러 메시지 해설 — “IndexError: list index out of range 원인이 뭐야?”
  • 이미 작성한 내 코드의 오류 원인에 대한 힌트 요청(코드 자체 생성은 요청하지 않음)
  • 용어 번역·개념 요약, 수업 자료 복습 질문
조건부 허용 (출처 명시 필수)

AI의 의견을 참고하되, 최종 판단과 반영 여부는 본인이 결정하고 성찰일지에 반드시 기록해야 하는 항목.

  • 완성한 구현(선택한 자료구조·알고리즘)에 대한 복잡도 검토 요청 — “이 구현이 정말 O(N)이 맞는지 검토해줘”
  • 직접 작성한 코드에 대한 최적화 아이디어 제안 요청(제안만 참고, 코드는 직접 재작성)
  • 엣지 케이스(빈 자료구조·중복값 등) 브레인스토밍 도움
금지

적발 시 아래 3번 처리방안이 적용되는 항목. 요구사항이나 과제 원문을 그대로 AI에 입력해 결과물을 받는 모든 행위를 포함한다.

  • 과제 요구사항을 그대로 입력해 전체 코드를 생성받아 제출
  • AI가 작성한 코드를 그대로, 또는 변수명만 바꿔 제출
  • 복잡도 분석이나 구현 계획을 AI에게 대신 세우게 하여 제출
  • 성찰일지(선택 근거·풀이 과정 서술)를 AI로 대필
기준 판단 원칙 — “AI에게 무엇을 시켰는가”가 기준이다. 개념·문법·오류 원인을 묻는 것은 허용, 과제 요구사항이나 완성된 구현 자체를 입력해 결과물(코드·복잡도 분석·글)을 받아 제출하는 것은 금지다.
3AI 활용 지침 위반 시 처리 방안판별 → 1차 → 2차 → 자진신고 감경
판별제출 코드와 성찰일지의 서술 수준 불일치, 질의응답 시 복잡도 선택 근거를 설명하지 못하는 경우, 급격한 코드 스타일 변화, AI 문체 특징 등을 근거로 담당 교사가 1차 확인한다. 필요 시 간단한 구술 확인(복잡도 선택 이유 질문)을 진행한다.
1차 위반해당 과제 재작성 지시 및 해당 과제 점수 50% 감점. 학생과 개별 면담을 통해 AI 활용 허용범위를 재안내한다.
2차 위반 또는 명백한 전체 대필해당 과제 0점 처리. 학교 학업성실성(생활지도) 규정에 따른 별도 조치를 병행하며, 보호자에게 통지한다.
자진 신고 시 감경제출 전 스스로 금지 범위 활용 사실을 신고한 경우, 해당 부분을 본인이 다시 작성하는 조건으로 감점 폭을 완화(0점 대신 재작성+감점)한다.

PART Ⅱ · PERFORMANCE ASSESSMENT

알고리즘 문제 해결(20%) 평가 운영 지침

14주차에 실시하는 실전 알고리즘 문제 해결 수행평가의 응시 흐름, 자료·도구 활용 규정과 부정행위 시 처리 방안, 평가요소·배점 및 4단계 채점기준.

적용 성취기준 [12자구05-01], [12자구05-02], [12자구05-03] (단원5 · 14주차 학습 내용 기준)

1응시 흐름사전 공지 → 문제 배포 → 개별 풀이 → 제출 → 채점·해설
01
사전 공지

응시 범위(1~13주 자료구조·알고리즘 전 범위), 문제 유형(LeetCode 수준 3문항), 제한 시간(90분), 채점기준표를 응시 최소 1주 전에 공지한다.

02
문제 배포 및 응시 환경 확인

지정된 코딩 테스트 환경에서 문제를 개별 배포한다. 응시 직전 허용·금지 자료 및 도구 범위를 다시 안내한다.

03
개별 풀이 (제한시간 90분)

학생은 감독 하에 의사코드로 접근을 설계한 뒤 구현한다. 감독 교사는 순회하며 부정행위 여부를 관찰한다.

04
제출

작성한 코드와 실행 결과(테스트 케이스 통과 여부)를 지정된 방식으로 제출한다. 제출 이후에는 수정할 수 없다.

05
채점 및 해설

채점기준표에 따라 채점하고, 다음 차시에 문항별 해설과 함께 개별 피드백을 제공한다.

2응시 중 자료·도구 활용 규정허용 · 조건부 허용 · 금지 3단계

알고리즘 문제 해결 수행평가는 감독 하에 제한 시간 내 개별로 치러지는 평가로, ‘실전 문제 해결 능력’ 그 자체를 측정한다. 평소 실습 과제와 달리 응시 중 활용 가능한 자료·도구의 범위를 아래와 같이 엄격히 제한한다.

허용

사전에 배포되었거나 문제지에 포함된 자료만 활용 가능.

  • 수업 시간에 배포한 파이썬 표준 라이브러리 요약 인쇄물
  • 본인이 이전 주차에 직접 작성한 실습 코드 노트(손 필기 또는 인쇄물)
  • 문제지에 포함된 예시 입출력 및 제약 조건
조건부 허용 (감독 교사 확인 필수)

감독 교사를 통한 최소한의 확인만 허용하며, 풀이 방법에 대한 조력은 포함하지 않는다.

  • 문제의 한글 표현 자체가 이해되지 않는 경우 감독 교사에게 의미만 질의(풀이 방법은 질문 불가)
  • 컴퓨터 환경 오류(실행 안 됨 등) 발생 시 감독 교사에게 기술 지원 요청
금지

적발 시 아래 3번 처리방안이 적용되는 항목.

  • AI 챗봇, 인터넷 검색 등 온라인 자료 활용
  • 사전에 작성해 온 코드를 붙여넣거나 외부 저장매체를 반입
  • 다른 학생과의 논의, 화면 공유, 답안 교환
  • 감독 교사의 허가 없는 자료 반출입
기준 판단 원칙 — 본 수행평가는 “응시자 본인이 그 순간 스스로 풀어낼 수 있는가”를 측정한다. 사전에 허가된 인쇄 자료 외의 모든 외부 조력(AI·인터넷·타인·사전 작성 코드)은 금지된다.
3부정행위 적발 시 처리 방안판별 → 1차 → 2차 → 자진신고 감경

성취수준 (5단계)

A매우 우수객체 참조 모델을 완벽히 이해하여 복잡한 중첩 자료구조에서도 얕은/깊은 복사를 정확히 구분해 구현하며, 임의의 코드에 대해 Big-O·Ω·Θ를 엄밀히 산출하고 그 근거를 논리적으로 증명한다. 투 포인터를 포함한 최적화 기법을 스스로 발견하여 O(N²) 문제를 O(N)으로 개선하는 데 능숙하다.
B우수객체 참조와 가변/불변의 차이를 이해하여 대부분의 상황에서 얕은/깊은 복사를 올바르게 구현한다. 주요 연산의 시간 복잡도를 정확히 산출할 수 있으며, 안내에 따라 투 포인터 기법을 배열 문제에 적용할 수 있다.

D다소 부족객체 참조와 값 복사를 혼동하는 경우가 잦다. 반복문의 중첩 정도로만 복잡도를 판단하며, 정확한 Big-O 산출에 어려움을 겪는다.
E최소 성취 미도달변수와 객체 참조의 기본 개념을 구분하지 못하며, 알고리즘의 효율성을 비교·판단하는 근거를 제시하지 못한다.

단원 3탐색 효율화를 위한 비선형 자료구조
핵심 아이디어

데이터를 계층적·망형으로 조직하거나 키를 메모리 주소로 직접 매핑하면, 선형 탐색으로는 불가능한 수준의 탐색 효율을 얻을 수 있다.

내용 요소

지식·이해해시 충돌 해결 기법, 트리의 재귀적 구조와 BST, 완전 이진 트리 기반 힙, 그래프의 인접 행렬/리스트 표현
과정·기능dict·Counter·defaultdict를 활용한 빈도 집계 기능, 트리 순회(전/중/후위) 구현 기능, heapq를 이용한 우선순위 처리 기능, defaultdict(list)·제네레이터 기반 그래프 구축 기능
가치·태도문제의 데이터 특성에 맞는 자료구조를 선택하는 판단력, 재귀적 사고에 대한 친숙함

성취기준

  • [12자구03-01]불변 객체를 식별자로 활용해 unhashable type 오류를 피하고, dict·Counter·defaultdict로 데이터 빈도수를 집계하는 최적의 코드를 작성할 수 있다.
  • [12자구03-02]트리의 전/중/후위 순회를 재귀 함수로 구현하고, 가변 기본 인자 안티 패턴을 식별해 수정할 수 있다.
  • [12자구03-03]heapq 모듈로 우선순위 큐를 구현해 K번째 최댓값을 O(N log K)에 추출하고, defaultdict(list)와 제네레이터로 그래프를 모델링할 수 있다.

성취수준 (5단계)

A매우 우수해시 충돌 해결 원리까지 정확히 이해하여 상황에 맞는 최적의 집계 코드를 스스로 설계하며, 트리 순회와 힙 연산의 시간 복잡도를 정확히 분석한다. 인접 행렬과 인접 리스트의 효율성을 비교해 문제 상황에 맞는 그래프 표현을 주도적으로 선택한다.
B우수dict·Counter·defaultdict를 적절히 활용해 빈도 집계 문제를 해결하며, 트리 순회를 재귀로 정확히 구현한다. heapq와 defaultdict(list)를 안내에 따라 활용해 힙·그래프 문제를 해결한다.
C보통기본적인 dict 활용은 가능하나 unhashable type 오류 등에 취약하다. 트리 순회 구현에 오류가 잦고, 가변 기본 인자 버그를 스스로 발견하지 못한다.
D다소 부족해시 테이블·트리·힙·그래프의 개념적 차이를 부분적으로만 이해하며, 재귀 함수 작성에 어려움을 겪는다.
E최소 성취 미도달비선형 자료구조의 구조적 특징을 이해하지 못하며, 단순한 탐색조차 적절한 자료구조 없이 접근한다.
단원 4그래프 탐색과 알고리즘 설계 패러다임
핵심 아이디어

상태 공간을 체계적인 규칙(BFS/DFS)으로 탐색하거나, 문제를 하위 문제로 분해해 중복 계산을 캐시(DP)하거나 매 순간 최선을 선택(Greedy)하는 전략은 방대한 경우의 수를 다루는 근본적인 무기다.

내용 요소

지식·이해상태 공간 탐색과 Call Stack/Queue, 정렬 알고리즘의 복잡도, 이진 탐색의 성립 조건, 메모이제이션·타뷸레이션
과정·기능2차원 Grid 탐색 구현 기능, bisect 모듈 활용 기능, DP 테이블 설계 기능, Greedy 반례 검증 기능
가치·태도문제 유형에 맞는 알고리즘 패러다임을 선택하는 전략적 사고, 반례를 통해 접근을 비판적으로 검토하는 태도

성취기준

  • [12자구04-01]문제의 목적(최단 거리 보장 또는 연결 요소 추적)에 따라 BFS와 DFS를 구별하여 2차원 공간 탐색 문제에 적용할 수 있다.
  • [12자구04-02]bisect 모듈로 Lower/Upper Bound를 적용해 정렬된 데이터에서 고속 탐색을 수행할 수 있다.
  • [12자구04-03]DP 테이블을 설계해 중복 부분 문제를 해결하고, Greedy 알고리즘이 최적해를 보장하지 못하는 반례를 스스로 도출할 수 있다.

성취수준 (5단계)

A매우 우수문제 상황을 정확히 분석해 BFS/DFS 중 최적의 탐색 전략을 스스로 선택하고 구현하며, bisect를 활용한 고속 탐색 코드를 능숙하게 작성한다. DP의 상태 정의와 전이 방정식을 스스로 수립하고, Greedy가 실패하는 반례를 논리적으로 증명한다.
B우수BFS와 DFS의 차이를 이해하여 안내에 따라 적절히 적용하며, bisect 모듈로 이분 탐색 문제를 해결한다. 1차원 DP 배열을 설계할 수 있으며 Greedy와 DP의 차이를 이해한다.
C보통BFS·DFS 코드는 작성하나 문제 상황에 맞는 선택에는 어려움을 겪는다. DP 테이블 설계에 힌트가 필요하며, Greedy의 한계를 스스로 발견하지 못한다.
D다소 부족그래프 탐색 알고리즘의 기본 구조만 모방할 수 있으며, DP와 단순 재귀의 차이(메모이제이션)를 이해하지 못한다.
E최소 성취 미도달상태 공간 탐색이나 동적 계획법의 개념 자체를 이해하지 못하며, 무차별 대입 외의 접근을 시도하지 못한다.
단원 5실전 알고리즘 문제 해결과 종합 평가
핵심 아이디어

제한된 시간 안에서 상태 공간을 가지치기(Pruning)하며 탐색하는 백트래킹 능력과, 15주간 학습한 자료구조·알고리즘을 통합적으로 적용해 실전 문제를 해결하는 역량의 완성.

내용 요소

지식·이해상태 공간 트리의 가지치기(Pruning) 메커니즘, typing 모듈 기반 타입 힌팅
과정·기능백트래킹 기반 완전 탐색 구현 기능, 제한 시간 내 문제 분석·구현·검증을 수행하는 실전 문제 해결 기능
가치·태도시간 압박 속에서도 침착하게 접근하는 문제 해결 태도, 자신의 코드에 대한 근거를 논리적으로 설명하는 책임감

성취기준

  • [12자구05-01]상태 공간 트리에서 조건에 맞지 않는 경로를 즉시 가지치기(Pruning)하는 백트래킹 알고리즘을 구현할 수 있다.
  • [12자구05-02]typing 모듈을 이용한 타입 힌팅을 적용하며 제한 시간 내에 실전 수준의 알고리즘 문제를 정확하고 효율적으로 해결할 수 있다.
  • [12자구05-03]15주간 학습한 자료구조와 알고리즘 패러다임을 통합적으로 적용해 시간 및 공간 복잡도 제약을 만족하는 최적의 해법을 설계할 수 있다.

성취수준 (5단계)

A매우 우수복잡한 상태 공간에서도 효과적인 가지치기 조건을 스스로 설계해 백트래킹 문제를 신속히 해결하며, 제한 시간 내 3문항 모두를 최적의 복잡도로 해결한다. 자료구조·알고리즘을 자유롭게 넘나들며 최적의 해법을 설계하고 그 근거를 논리적으로 설명한다.
B우수기본적인 가지치기를 적용해 백트래킹 문제를 해결하며, 제한 시간 내 대부분의 문항에서 정확하고 효율적인 해법을 구현한다. 학습한 자료구조를 상황에 맞게 적용할 수 있다.
C보통가지치기 없는 완전 탐색은 구현하나 시간 초과에 취약하며, 제한 시간 내 일부 문항만 해결한다. 자료구조 선택에 안내가 필요하다.
D다소 부족백트래킹의 기본 구조를 부분적으로만 모방하며, 제한 시간 내 문제 해결에 큰 어려움을 겪는다.
E최소 성취 미도달실전 상황에서 학습한 자료구조·알고리즘을 전혀 적용하지 못하며, 문제 분석조차 스스로 수행하지 못한다.
