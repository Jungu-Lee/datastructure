자리수 연결 리스트 덧셈

오늘 배운 노드(data/next), 더미 노드, head/tail만으로 두 개의 "숫자 열차"를 하나로 합쳐야 한다. 자리 올림(carry)과 서로 다른 길이의 열차를 빠뜨림 없이 처리하는 것, 그리고 리스트를 뒤집지 않고 결과를 사람이 읽는 순서로 출력하는 것이 이번 과제의 두 가지 핵심 도전이다.

01 배경 & 문제 정의

정수 하나를 연결 리스트로 표현할 때, 각 노드가 숫자 하나(자리수, 0~9)를 싣고, head가 1의 자리(최하위 자리)를 가리킨다고 약속한다. 예를 들어 342는 다음과 같이 표현된다.

342를 나타내는 연결 리스트 (head = 1의 자리)

head부터 순서대로 읽으면 2, 4, 3 — 즉 뒤에서부터(낮은 자리부터) 숫자가 저장된다. 이렇게 저장하면 덧셈이 항상 head에서 시작되어, 인덱스 접근이나 자릿수 계산 없이 next만 따라가며 계산할 수 있다.

문제. 위와 같은 방식으로 표현된 두 연결 리스트 l1, l2가 주어진다. 두 수를 더한 결과를, 같은 방식(head = 1의 자리)으로 표현한 새 연결 리스트로 반환하는 add_numbers(l1, l2)를 작성하라.

예시 1

342 + 465

= 807

예시 2 · 길이가 다름

9999 + 8

= 10007

예시 3 · 자릿수 증가

999 + 1

= 1000

02 요구사항

① int_to_list(n) — 정수를 연결 리스트로 변환

add_numbers는 연결 리스트 두 개를 입력으로 받는다. 그런데 아래 테스트 케이스는 342, 465 같은 정수로 주어져 있으므로, 그 전에 정수를 연결 리스트로 바꿔주는 변환 함수가 먼저 있어야 실제로 테스트를 돌릴 수 있다.

  • ·정수 n을 받아, 각 자리수를 담은 노드들을 head가 1의 자리가 되도록 연결한 리스트의 head를 반환하는 int_to_list(n)을 작성한다.
  • ·n // 10, n % 10으로 자리수를 하나씩 뽑아내면서 노드를 이어 붙이는 방식을 권장한다 (문자열로 바꿔 뒤집는 방식은 지양 — 몫/나머지 연산으로 자리수를 분리하는 감각이 이번 과제의 연습 대상이다).
  • ·n = 0인 경우도 처리해야 한다 (자리수 0 하나만 담은 노드 1개짜리 리스트를 반환).

② add_numbers(l1, l2) 구현

  • ·3주차에 만든 Node(data, next)를 그대로 사용한다. LinkedList 클래스를 확장해서 써도 되고, 함수 하나로 자유롭게 작성해도 된다.
  • ·각 자리를 더하면서 자리 올림(carry)을 다음 자리 계산에 반영해야 한다.
  • ·두 리스트의 길이가 다른 경우를 처리해야 한다 (짧은 쪽이 끝나도 긴 쪽과 carry는 계속 처리).
  • ·마지막 자리까지 다 더한 뒤에도 carry가 남아있으면 새 노드를 추가해서 자릿수가 늘어나야 한다 (예: 999+1=1000).
  • ·l1, l2를 각각 head부터 한 번씩만 순회해야 한다 — 인덱스로 접근하거나 길이를 미리 세기 위해 따로 순회하는 것은 금지. 전체 시간복잡도가 O(max(N, M))임을 코드 주석으로 설명할 것.

③ print_number(head) — 사람이 읽는 순서로 출력

결과 리스트는 head가 1의 자리이므로, head부터 그대로 출력하면 807이 7 0 8처럼 거꾸로 나온다. 가장 높은 자리부터 8 0 7 순서로 출력하는 print_number(head)를 작성하라.

제약 조건. 리스트의 next 포인터를 바꾸거나(reverse) 새 리스트를 뒤집어서 만드는 것은 금지한다. 원본 리스트 구조는 그대로 유지한 채, 출력되는 순서만 뒤집혀야 한다.
힌트. 리스트를 물리적으로 뒤집지 않고 방문 순서만 뒤집는 방법이 있다. 함수가 자기 자신을 호출하는 방식(재귀)을 떠올려보자 — 재귀 호출이 next를 따라 끝까지 들어갔다가, 되돌아 나오면서(return) 무언가를 하면 어떤 순서로 처리될까?

④ 테스트

int_to_list로 l1, l2를 만들고, add_numbers에 넣어 실행한 뒤, 결과를 print_number로 출력한다. 아래 세 가지 케이스를 반드시 직접 실행해서 결과를 확인하고, 코드와 함께 실행 결과(출력 캡처 또는 콘솔 로그)를 제출한다.

03 서술형 질문

구현을 마친 뒤, 아래 질문에 각 3~5문장으로 답하시오.

  1. add_numbers의 시간복잡도와, 새로 생성하는 노드 수를 기준으로 한 공간복잡도를 각각 설명하시오.
  2. print_number를 재귀로 구현했다면, 재귀 호출이 가장 깊어졌을 때 그 깊이는 무엇에 비례하는가? 만약 자릿수가 10만 자리인 매우 큰 수라면 이 방식에 어떤 위험이 있을 수 있는가?
  3. 만약 문제의 조건이 바뀌어서 head가 "1의 자리"가 아니라 "가장 높은 자리"(예: 342를 head→3→4→2→None으로 저장)로 주어진다면, 지금 작성한 add_numbers를 그대로 쓸 수 있는가? 왜 그런지, 혹은 왜 안 되는지 설명하시오.

05 제출 전 자가 점검

제출하기 전에 아래 항목을 스스로 점검해보자.

  • int_to_list(n)이 모든 자리수를 빠짐없이 변환하고, n=0인 경우도 처리한다.
  • 두 리스트의 자리수를 더하면서 carry를 다음 자리로 넘겼다.
  • l1, l2 길이가 다른 경우(9999 + 8)를 테스트해서 정확한 결과를 확인했다.
  • 마지막 carry로 자릿수가 늘어나는 경우(999 + 1)를 테스트해서 정확한 결과를 확인했다.
  • l1, l2를 각각 한 번씩만 순회했고, 그 이유를 주석으로 O(max(N,M))라고 설명했다.
  • print_number에서 next 포인터를 바꾸거나 리스트를 뒤집지 않았다.
  • 세 가지 서술형 질문(복잡도, 재귀 깊이, 역방향 조건)에 모두 답했다.
