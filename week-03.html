01 학습 목표 & 핵심 질문

핵심 아이디어

물리적인 메모리의 연속성을 포기하면, 데이터의 삽입과 삭제 속도를 극대화할 수 있다.

핵심 질문

배열처럼 연속된 메모리 공간이 부족할 때, 흩어진 데이터를 어떻게 하나의 기차처럼 이어 붙일 수 있을까?

학습 목표

이번 차시를 마치면 아래 네 가지를 스스로 할 수 있어야 한다. 각 목표는 06 자가진단 항목과 연결된다.

  • ①노드가 data와 next로 이루어진다는 것을 설명하고, 더미 노드가 왜 필요한지 빈 리스트 예외를 예로 들어 근거를 제시할 수 있다.
  • ②__slots__와 더미 노드를 적용해 단일 연결 리스트의 append와 순회를 결함 없이 설계할 수 있다.
  • ③insert_at·delete_value·search를 구현하고 각 연산의 시간 복잡도를 산출하며, 삽입이 왜 "조건부 O(1)"인지 배열과 비교해 설명할 수 있다.
  • ④빈 리스트, tail 갱신 누락 같은 엣지 케이스에서 생기는 오류를 스스로 찾아 방어할 수 있다.
[12자구02-01]

포인터 기반의 단일 연결 리스트를 더미 노드와 __slots__를 활용해 결함 없이 구현할 수 있다.

2주차 복습

지난주 배운 파이썬 리스트는 insert(0, x)가 O(N)이었다 — 좌석이 번호대로 붙은 기차라서, 앞에 새 칸을 끼우려면 뒤 칸을 전부 밀어야 했다. 연결 리스트는 각 칸이 "다음 칸이 어디 있는지"만 기억하게 해서 이 문제를 근본적으로 피한다.

02 이론

객차가 연결된 기차

연결 리스트의 한 칸을 노드(Node)라 부른다. 노드는 data(싣고 있는 값)와 next(다음 칸에 대한 참조) 두 가지만 가진다. 마지막 칸의 next는 None — "여기서 열차가 끝난다"는 정지 신호다. head가 첫 칸을 가리키고 있으면, next를 따라가며 전체 열차를 순서대로 방문할 수 있다.

노드 구조 & 연결 관계

두 그림에서 노드의 생김새는 완전히 같다 — 왼쪽 칸은 data(값), 오른쪽 칸의 점은 next 참조이고, 마지막 노드의 next는 None이다. 달라지는 것은 맨 앞에 무엇이 있느냐뿐이다. ①은 head라는 변수가 첫 노드를 직접 가리키는 교과서 기본형이고, ②는 값 없는 더미 노드를 항상 앞에 하나 두어 dummy.next가 head의 역할을 대신하는 방식이다.

04 실습의 코드는 ② 방식을 쓴다. 그래서 LinkedList에는 head라는 이름의 변수가 아예 없고, 순회도 self.dummy.next부터 시작한다. 왜 굳이 빈 칸을 하나 더 두는지는 04 실습에서 다룬다 — 리스트가 비어 있든 아니든 "앞 노드가 항상 존재한다"는 상태를 만들어 삽입·삭제 코드에서 예외 처리를 없애기 위해서다.

O(1) 삽입, 그 조건은?

"연결 리스트는 삽입이 O(1)"이라는 말은 조건부 진실이다. 이미 삽입 위치를 가리키는 참조를 손에 쥐고 있어야 O(1)이다. head 삽입은 O(1)이지만, "값이 42인 칸 뒤에 삽입"처럼 위치를 찾아야 하는 경우는 탐색 자체가 O(N)이다.

→ "연결 리스트가 빠르다"가 아니라 "연결 지점을 이미 알고 있다면 그 지점의 삽입/삭제가 빠르다"가 정확한 표현이다.

필수 구현 연산 (CRUD)

연결 리스트를 코드로 직접 구현할 때 반드시 작성해야 하는 핵심 메서드들이다. 시간 복잡도와 함께 묶어서 기억해야 한다.

1. 삽입(Insertion)

연산복잡도설명
맨 앞(Head)에 삽입O(1)head 참조만 있으면 탐색 없이 즉시 연결
맨 뒤(Tail)에 삽입O(1) / O(N)tail 포인터가 있으면 O(1), 없으면 head부터 순회해야 하므로 O(N)
중간 특정 위치에 삽입O(N) 탐색 + O(1) 연결위치를 찾는 데 O(N)이 걸리지만, 위치를 이미 안다면 포인터 변경만으로 O(1)에 삽입 가능

2. 삭제(Deletion)

연산복잡도설명
맨 앞 노드 삭제O(1)head를 head.next로 옮기기만 하면 됨
특정 값/위치의 노드 삭제O(N)삭제할 노드의 "이전 노드"를 찾아야 하므로 head부터 순회 필요

3. 탐색(Search / Traversal)

연산복잡도설명
값으로 노드 찾기O(N)인덱스로 바로 접근할 수 없으므로, head부터 원하는 값을 찾을 때까지 순차적으로 이동

→ 배열은 "위치(인덱스)"로 O(1) 접근이 가능하지만, 연결 리스트는 "연결 관계"만 알 뿐 위치를 모르므로 탐색은 항상 O(N)이다. 이 차이가 두 자료구조를 언제 선택할지 가르는 기준이 된다.

03 체험 활동

버튼을 눌러 삽입·삭제·탐색을 직접 실행하며, 각 연산이 왜 O(1)이거나 O(N)인지 몸으로 확인해보자. 탐색 과정은 노드를 하나씩 훑는 모습을 그대로 보여준다.

아직 열차가 없다. head에 삽입을 눌러 첫 칸을 만들어보자.

04 실습

__slots__로 노드 속성을 data, next로 못박아 메모리를 절약한다.

class Node:
    __slots__ = ('data', 'next')
    def __init__(self, data):
        self.data = data
        self.next = None

더미 노드로 빈 리스트 예외 없애기

더미 노드는 데이터 없는 "가짜 첫 칸"을 항상 만들어 두어, "리스트가 비었을 때"와 "이미 노드가 있을 때"를 같은 코드로 처리하게 해준다.

__init__ → append 과정 추적
STEP 1 · __init__()

self.dummy = Node(None) — 데이터 없는 더미 노드 하나를 만든다. self.tail = self.dummy — 아직 진짜 데이터가 없으니 tail도 일단 dummy를 가리킨다.

STEP 2 · append(10)

new_node = Node(10) 생성 → self.tail.next = new_node (dummy.next가 채워짐) → self.tail = new_node. dummy 바로 뒤에 첫 실제 노드가 연결됐다.

STEP 3 · append(7)

new_node = Node(7) 생성 → self.tail.next = new_node (10의 next가 채워짐) → self.tail = new_node. tail이 7로 이동했다.

STEP 4 · append(42)

new_node = Node(42) 생성 → self.tail.next = new_node (7의 next가 채워짐) → self.tail = new_node. tail이 42로 이동했고, 42.next는 여전히 None이다 — 지금 리스트의 진짜 끝이라는 뜻이다.

① self.dummy — tail도 처음엔 더미를 가리켜야 append 로직이 일관된다.
② new_node — 마지막 칸의 next에 새 노드를 연결.
③ new_node — tail을 새 노드로 갱신해야 다음 append도 O(1).
④ self.dummy.next — 순회는 진짜 첫 칸부터.

삽입 위치 지정, 삭제, 탐색 완성하기

위 LinkedList 클래스에 insert_at, delete_value, search를 이어서 구현해보자. 각각 위 이론 표의 어떤 복잡도에 해당하는지 떠올리며 빈칸을 채운다.

insert_at(1, 99) 호출 — 새 노드가 index 1 앞에 삽입되는 과정

현재 리스트: dummy → 10 → 7 → 42 → None. index 1은 지금 7이 차지한 자리다 — 새 노드는 그 자리를 밀어내고 들어간다.

STEP 1 · 탐색 시작

new_node = Node(99) 생성 → prev = self.dummy. new_node는 아직 어디에도 연결되지 않은 채(next=None) 따로 떠 있다.

STEP 2 · 탐색 진행 (①)

for _ in range(1): prev = prev.next — prev가 dummy에서 10으로 한 칸 이동했다. index만큼 반복하는 이 탐색이 O(N)이다. (빈칸 ①의 정답이 prev.next인 이유)

STEP 3 · new_node.next = prev.next

new_node.next = prev.next — 새 노드(99)의 next가 먼저 7을 가리키도록 연결한다(점선 화살표). 10 → 7의 기존 연결은 아직 끊어지지 않았다 — 그래서 뒤쪽 리스트(7, 42)를 잃어버리지 않는다.

STEP 4 · prev.next = new_node (②, 완료)

prev.next = new_node — 10의 next가 새 노드(99)로 다시 연결된다(빈칸 ②의 정답이 new_node인 이유). 최종 순서: dummy → 10 → 99 → 7 → 42 → None. new_node.next는 이미 7을 가리키고 있었으므로 뒤쪽 연결은 끊기지 않는다. 42가 여전히 tail이므로 if new_node.next is None 분기는 이번엔 실행되지 않는다.

① prev.next — index만큼 앞으로 이동해 삽입 직전 노드를 찾는다(O(N) 탐색).
② new_node — 찾은 위치의 다음 자리에 새 노드를 끼워 넣는다(O(1) 연결).
③ cur.next — 삭제 대상을 건너뛰도록 이전 노드의 next를 다시 연결한다.
④ prev — 삭제한 노드가 tail이었다면 tail 포인터도 함께 갱신해야 다음 append가 안전하다.
⑤ += 1 — 매 비교마다 인덱스를 늘려가며 head부터 순차 탐색한다.
