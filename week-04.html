01 핵심 아이디어 & 핵심 질문

핵심 아이디어

다중 포인터의 논리적 조작을 통해 선형 자료구조의 탐색 한계와 제약을 우회할 수 있다.

핵심 질문

앞으로만 갈 수 있는 연결 리스트에서 데이터를 역순으로 뒤집거나 순환(사이클)을 어떻게 감지할까? 그리고 뒤로도 갈 수 있게 하거나, 끝을 다시 처음으로 잇는다면 무엇이 달라질까?

3주차 복습

지난주 만든 Node(data, next)와 더미 노드 구조가 이번 주의 재료다. next를 한 번 잘못 덮어쓰면 뒤 칸으로 가는 유일한 길을 영영 잃어버린다는 것을 기억하며 시작하자.

이번 주에 다룰 네 가지 변형

  • ①연결 리스트 뒤집기 — next 방향을 통째로 뒤바꾸기
  • ②순환(사이클) 감지 — 토끼와 거북이로 무한 루프 찾아내기
  • ③이중 연결 리스트 — prev를 추가해 양방향으로 걷기
  • ④원형 연결 리스트 — 꼬리를 다시 머리로 이어 끝없이 순환하기

02 이론

연결 리스트 뒤집기: next를 거꾸로 다시 잇기

배열이라면 인덱스를 반대로 읽으면 그만이지만, 연결 리스트는 물리적으로 next 방향을 뒤집어야 한다. prev, cur, nxt 세 개의 포인터를 한 칸씩 같이 이동시키며 cur.next = prev로 화살표 방향을 하나씩 뒤집으면, 추가 메모리 없이 O(N)에 전체를 뒤집을 수 있다.

아래 다이어그램에서 각 노드는 data와 next, 두 개의 속성(필드)을 가진 객체로 그려진다. 화살표는 항상 그 노드의 next 속성값이다 — 뒤집기란 결국 각 노드의 next 필드에 어떤 값을 다시 써넣는지의 문제일 뿐, 노드 자체나 데이터는 전혀 움직이지 않는다.

6개의 노드(A~F)를 하나씩 처리하며, 반전된 부분이 왼쪽에서부터 한 칸씩 자라나는 과정을 끝까지 따라가보자.

prev=None, cur=A

원본 상태: A → B → C → D → E → F → None. 아직 아무 next 필드도 바뀌지 않았다.

prev=A, cur=B

A의 next 필드가 None으로 바뀌었다. 반전된 부분: A→None. 남은 원본: B→C→D→E→F→None.

prev=B, cur=C

B의 next 필드가 A로 바뀌었다. 반전된 부분: B→A→None. 남은 원본: C→D→E→F→None.

prev=C, cur=D

C의 next 필드가 B로 바뀌었다. 반전된 부분: C→B→A→None. 남은 원본: D→E→F→None.

prev=D, cur=E

D의 next 필드가 C로 바뀌었다. 반전된 부분: D→C→B→A→None. 남은 원본: E→F→None.

prev=E, cur=F

E의 next 필드가 D로 바뀌었다. 반전된 부분: E→D→C→B→A→None. 남은 원본: F→None.

prev=F, cur=None

F의 next 필드가 E로 바뀌었다. cur가 None이 되어 반복 종료. 모든 next 필드가 다시 쓰여 F→E→D→C→B→A→None이 완성됐다. 새로운 head는 F다.

토끼와 거북이 (Fast & Slow Pointers)

순환 연결 리스트는 계속 순회하면 끝나지 않고 무한 루프에 빠진다. 두 배 빠른 포인터(토끼)와 한 칸씩 가는 포인터(거북이)를 동시에 출발시키면, 순환이 있을 경우 토끼가 결국 거북이를 만난다 — 트랙을 도는 두 러너가 속도 차이 때문에 언젠가 같은 지점에서 마주치는 것과 같은 원리다.

A→B→C가 꼬리, D→E→F→G→H→I→(다시 D)가 순환 구간인 9개 노드짜리 리스트에서, 두 포인터가 만날 때까지 한 번의 이동도 놓치지 않고 따라가보자.

slow=A, fast=A

거북이(slow)와 토끼(fast)를 모두 head(A)에서 동시에 출발시킨다. 꼬리 A-B-C를 지나야 순환 구간(D~I)에 들어선다.

slow=B, fast=C

한 번 이동: slow는 한 칸(B), fast는 두 칸(C) 움직인다. 아직 둘 다 꼬리 구간에 있다.

slow=C, fast=E

slow는 C로 꼬리 끝에 도달했다. fast는 두 칸을 더 가 순환 구간 안쪽 E까지 진입했다.

slow=D, fast=G

slow가 드디어 순환 구간에 진입(D)했다. fast는 이미 순환 구간을 절반 넘게 돌아 G에 있다.

slow=E, fast=I

slow는 E로 한 칸 전진. fast는 순환 구간을 거의 한 바퀴 돌아 I까지 왔다 — 둘의 간격이 좁혀지고 있다.

slow=F, fast=E

slow는 F로 이동. fast는 I에서 두 칸을 더 가 D를 지나 다시 E로 — slow를 거의 따라잡았다.

slow=G, fast=G

slow와 fast가 G에서 만났다! 순환 구간 안에서는 fast가 매 반복 slow보다 한 칸씩 더 앞서므로, 언젠가 반드시 slow를 따라잡는다 — 이것이 순환이 존재한다는 증거다.

03 이중 연결 리스트 (Doubly Linked List)

지금까지의 열차는 한 방향으로만 달렸다. 각 칸이 next 뿐 아니라 prev도 들고 있다면 어떨까? 앞 칸과 뒤 칸을 모두 가리키는 순간, 열차는 양방향으로 걸을 수 있는 구조가 된다.

C

None
트레이드오프 — prev 포인터 하나가 늘어난 만큼 노드가 차지하는 메모리도 늘고, 삽입·삭제 때 갱신해야 할 링크 수도 두 배가 된다. 공짜로 얻는 능력은 없다: 양방향 탐색이라는 편리함은 메모리와 코드 복잡도라는 비용과 맞바꾼 것이다.

구현: Node와 DoublyLinkedList

class Node:
    def __init__(self, data):
        self.data = data
        self.prev = None
        self.next = None

class DoublyLinkedList:
    def __init__(self):
        self.head = None
        self.tail = None   # 마지막 노드도 O(1)에 접근하기 위해 저장

    def append(self, data):
        new_node = Node(data)
        if self.head is None:
            self.head = new_node
            self.tail = new_node
        else:
            new_node.prev = self.tail
            self.tail.next = new_node
            self.tail = new_node

핵심 연산: O(1) 삭제의 비밀

단일 연결 리스트에서 노드 하나를 지우려면, 그 노드의 앞 노드(prev)를 찾기 위해 head부터 순회해야 했다(O(N)). 이중 연결 리스트는 노드 자신이 prev를 이미 들고 있으므로, 노드에 대한 참조만 있으면 앞뒤를 순회하지 않고 곧바로 링크를 재배선할 수 있다.

def delete_node(self, node):
    if node.prev:
        node.prev.next = node.next
    else:
        self.head = node.next        # node가 head였던 경우

    if node.next:
        node.next.prev = node.prev
    else:
        self.tail = node.prev        # node가 tail이었던 경우

04 원형 연결 리스트 (Circular Linked List)

이번엔 반대로 생각해보자. 마지막 칸이 None을 가리키는 대신, 다시 첫 칸을 가리키게 만들면 어떻게 될까? 끝이 없는 순환 선로가 만들어진다. 단일 연결 리스트에도, 이중 연결 리스트에도 이 아이디어를 적용할 수 있다 (원형 단일 / 원형 이중).

C.next가 다시 A(head)를 가리켜 None이 존재하지 않는다.

순회 시 주의 — 기존 while cur: 조건을 그대로 쓰면 cur는 절대 None이 되지 않으므로 무한 루프에 빠진다. 반드시 "출발점으로 되돌아왔는가"를 종료 조건으로 써야 한다: while True: ... if cur.next == head: break 또는 while cur.next != head:.

구현: Node와 CircularLinkedList

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class CircularLinkedList:
    def __init__(self):
        self.head = None
        self.tail = None   # tail.next는 항상 head를 가리킨다

    def append(self, data):
        new_node = Node(data)
        if self.head is None:
            self.head = new_node
            new_node.next = new_node     # 자기 자신을 가리키며 시작
            self.tail = new_node
        else:
            new_node.next = self.head
            self.tail.next = new_node
            self.tail = new_node

    def traverse(self):
        if self.head is None:
            return []
        result, cur = [], self.head
        while True:
            result.append(cur.data)
            cur = cur.next
            if cur == self.head:   # 출발점으로 되돌아오면 종료
                break
        return result

원형 리스트가 만드는 알고리즘: 요세푸스 문제

N명이 원을 이루어 앉아 k번째 사람마다 탈락시키는 요세푸스(Josephus) 문제는 원형 연결 리스트로 자연스럽게 표현된다. 포인터가 한 방향으로 계속 k칸씩 이동하며 노드를 제거하는데, 원형이므로 "마지막 사람 다음은 다시 첫 사람"이라는 규칙을 별도 분기 없이 그대로 표현할 수 있다.

구체적인 예시: 5명, k=2

1, 2, 3, 4, 5가 원탁에 앉아 1부터 세기 시작해 2번째로 세어지는 사람마다 탈락한다고 하자. 탈락한 사람 다음 사람부터 다시 1을 세기 시작한다.

라운드이번 라운드 시작 시 남은 사람세는 순서탈락자
11, 2, 3, 4, 51(1) → 2(2)2
21, 3, 4, 53(1) → 4(2)4
31, 3, 55(1) → 1(2)1
43, 53(1) → 5(2)5

탈락 순서: 2 → 4 → 1 → 5  ·  마지막까지 남은 생존자: 3

코드로 구현하기

위에서 만든 CircularLinkedList에 원소를 채운 뒤, "k-1번 이동 → 그다음 사람 탈락"을 인원이 한 명 남을 때까지 반복하면 된다.

# 알고리즘: 요세푸스 문제 (원형 연결 리스트 활용)
# 1) 사람들을 원형 연결 리스트로 구성한다 (마지막 사람의 next가 다시 첫 사람을 가리킴)
# 2) cur를 tail(마지막 사람)에 두어, cur.next가 "이번 라운드에서 셀 첫 번째 사람"이 되게 한다
# 3) 남은 인원이 1명을 초과하는 동안 반복한다
#    3-1) cur를 (k-1)번 다음으로 이동시켜, k번째로 셀 사람 바로 앞에 멈춘다
#    3-2) cur.next(= k번째로 세어진 사람)를 탈락자로 기록한다
#    3-3) cur.next가 탈락자의 다음 사람을 가리키도록 재배선해, 탈락자를 원형에서 건너뛴다
#    3-4) 남은 인원수를 1 줄인다 (cur 자신은 다음 라운드의 "시작 직전" 자리를 그대로 유지한다)
# 4) 반복이 끝나면 cur가 가리키는 사람이 마지막 생존자다
def josephus_circular(people, k):
    circle = CircularLinkedList()
    for p in people:
        circle.append(p)

    cur = circle.tail          # cur.next가 "이번 라운드 첫 카운트"
    remaining = len(people)
    eliminated_order = []

    while remaining > 1:
        for _ in range(k - 1):
            cur = cur.next
        victim = cur.next
        eliminated_order.append(victim.data)
        cur.next = victim.next  # 탈락자를 건너뛰도록 재배선 (원형 유지)
        remaining -= 1

    return cur.data, eliminated_order


# 위 표와 동일한 예시로 확인해보기
people = [1, 2, 3, 4, 5]
survivor, order = josephus_circular(people, k=2)
print("탈락 순서:", order)     # [2, 4, 1, 5]
print("생존자:", survivor)     # 3

05 실전에서는 어디에 쓰일까?

이중/원형 연결 리스트는 교과서에만 등장하는 개념이 아니다. 아래는 실제 소프트웨어에서 이 구조들이 뼈대로 쓰이는 대표적인 상황이다.

DOUBLY

브라우저 뒤로/앞으로 가기

방문한 페이지를 노드로 연결한다. "뒤로"는 prev로, "앞으로"는 next로 이동하면 되므로 이중 연결 리스트가 정확히 들어맞는다.

Node = { url, prev, next }
prev → 바로 이전에 방문한 페이지, next → 뒤로 갔다가 다시 앞으로 갈 페이지

DOUBLY

실행 취소 / 다시 실행 (Undo/Redo)

텍스트 에디터의 각 편집 상태를 노드로 연결하면, Ctrl+Z는 prev로, Ctrl+Y는 next로 이동하는 것과 같다.

Node = { snapshot(편집 상태), prev, next }
prev → 이 편집을 하기 직전 상태, next → 다시 실행(Redo) 시 돌아갈 상태

DOUBLY

LRU 캐시

최근 사용한 항목을 리스트 앞으로 옮기고 오래된 항목을 뒤에서 제거한다. 노드 참조만 있으면 O(1)로 삭제·이동이 가능한 이중 연결 리스트의 장점을 그대로 활용한다.

Node = { key, data, prev, next }
prev → 나보다 더 최근에 쓰인 노드, next → 나보다 더 오래 전에 쓰인 노드 · 해시맵이 key → 이 노드에 대한 참조를 별도로 들고 있다

CIRCULAR

음악 플레이어 "전체 반복"

마지막 곡 다음에 다시 첫 곡이 재생되어야 한다. 원형 연결 리스트라면 별도의 "처음으로 되돌리기" 분기 없이 next만 계속 따라가면 된다.

Node = { song(곡 정보), next }
next → 다음 곡 (단, 마지막 곡의 next는 다시 첫 곡을 가리킨다 → None이 존재하지 않음)

CIRCULAR

라운드 로빈 CPU 스케줄링

여러 프로세스에 순서대로 짧은 시간을 할당하고, 끝나지 않은 프로세스는 다시 대기열 뒤로 보낸다. 원형 구조이므로 마지막 프로세스 다음이 자연스럽게 첫 프로세스로 이어진다.

Node = { process(프로세스 정보), next }
next → 대기열에서 다음 순서의 프로세스 (끝까지 돌면 다시 맨 처음 프로세스로 이어짐)

CIRCULAR

요세푸스 문제 · 카드 돌리기

원탁 게임처럼 순서를 계속 돌며 조건에 맞는 노드를 제거하는 문제는 원형 연결 리스트로 자연스럽게 모델링된다.

Node = { person(참가자 번호), next }
next → 원탁에서 내 다음 사람 · 한 사람이 탈락하면 그 앞 사람의 next가 탈락자를 건너뛰고 그 다음 생존자를 가리키도록 재배선된다

class Playlist(CircularLinkedList):

def move_to_front(self, node):
    # 이중 연결 리스트이므로 node.prev로 즉시 접근해 O(1)에 떼어낸다
    self.delete_node(node)          # 위에서 만든 O(1) 삭제 재사용

    if self.head:
        self.head.prev = node
    self.head = node                 # "가장 최근 사용"은 항상 맨 앞

06 체험 활동

A → B → C → None을 뒤집는 과정을, 코드 한 줄 한 줄이 다이어그램에서 정확히 어떤 변화를 일으키는지 함께 따라가보자.

def reverse_list(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev = cur
        cur = nxt
    return prev

prev=None, cur=A

초기화: prev=None, cur=head(A). 아직 아무 화살표도 바뀌지 않았다 — 코드 2~3번째 줄이 지금 실행된 부분이다.

nxt = cur.next → nxt=B

5번째 줄 실행: cur(A)의 next를 잃어버리기 전에 nxt에 저장한다. 아직 A→B 화살표는 그대로다.

cur.next = prev → A.next=None

6번째 줄 실행: A의 화살표가 뒤집혔다! A→B였던 화살표가 A→None이 됐다. (다이어그램의 앰버색 화살표가 방금 바뀐 부분)

prev = cur → prev=A

7번째 줄 실행: prev가 A로 이동한다. 화살표는 바뀌지 않는다 — 포인터만 이동한다.

cur = nxt → cur=B

8번째 줄 실행: cur가 저장해둔 nxt(B)로 이동한다. 1번째 반복이 끝났다 — 다시 4번째 줄(while cur:)로 돌아간다.

nxt = cur.next → nxt=C

2번째 반복 시작. 5번째 줄: cur(B)의 next(=C, 아직 원본 그대로)를 nxt에 저장한다.

cur.next = prev → B.next=A

6번째 줄: B의 화살표가 뒤집혔다! B→C였던 화살표가 B→A가 됐다. A→None은 그대로 유지된다.

prev = cur → prev=B

7번째 줄: prev가 B로 이동한다.

cur = nxt → cur=C

8번째 줄: cur가 C로 이동한다. 2번째 반복 종료.

nxt = cur.next → nxt=None

3번째 반복 시작. 5번째 줄: cur(C)의 next(=None, C는 원래 마지막 노드였다)를 nxt에 저장한다.

cur.next = prev → C.next=B

6번째 줄: C의 화살표가 뒤집혔다! C→None이었던 화살표가 C→B가 됐다. 이제 C→B→A→None으로 완전히 연결됐다.

prev = cur → prev=C

7번째 줄: prev가 C로 이동한다.

cur = nxt → cur=None

8번째 줄: cur가 None으로 이동한다. 다음에 4번째 줄(while cur:)을 검사하면 조건이 거짓이 되어 반복이 끝난다.

4번째 줄에서 cur가 None이라 반복이 종료되고, 9번째 줄 return prev가 실행된다. prev(C)가 새로운 head다. 결과: C → B → A → None

원형 리스트 A → B → C → (다시 A)를 순회하는 코드를 한 줄씩 실행하며, cur가 어떻게 움직이고 언제 멈추는지 살펴보자.

def traverse(self):
    if self.head is None:
        return []
    result, cur = [], self.head
    while True:
        result.append(cur.data)
        cur = cur.next
        if cur == self.head:
            break
    return result

result=[], cur=head(A)

초기화: head가 None이 아니므로(2번째 줄) 그냥 지나가고, result와 cur를 준비한다(4번째 줄). 아직 아무 노드도 방문하지 않았다.

result.append(A)

6번째 줄 실행: A를 방문해 result에 담는다. A가 초록색(방문 완료)으로 바뀐다.

cur=cur.next(→B), B==head? 아니오

7번째 줄: cur가 B로 이동한다. 8번째 줄: B는 head(A)가 아니므로 반복을 계속한다.

result.append(B)

6번째 줄: B를 방문해 result에 담는다. B도 초록색이 된다.

cur=cur.next(→C), C==head? 아니오

7번째 줄: cur가 C로 이동한다. 8번째 줄: C도 head가 아니므로 계속 진행한다.

result.append(C)

6번째 줄: C를 방문해 result에 담는다. 이제 A, B, C 모두 방문했다.

cur=cur.next(→A), A==head? 예!

7번째 줄: cur가 다시 A로 이동한다. 8번째 줄: A는 head와 같다! 여기서 멈추지 않으면 무한 루프에 빠진다.

9번째 줄 break로 반복이 종료되고, 10번째 줄 return result가 실행된다. 결과: [A, B, C]를 방문하고 종료.

# 알고리즘: 토끼와 거북이 (Floyd's Cycle Detection)
# 1) slow, fast를 모두 head에서 동시에 출발시킨다
# 2) fast와 fast.next가 둘 다 존재하는 동안 반복한다
#    2-1) slow는 한 칸, fast는 두 칸 이동한다
#    2-2) slow와 fast가 같은 노드를 가리키면 순환이 존재하므로 True
# 3) fast(또는 fast.next)가 None에 닿으면 순환 없이 끝까지 갔다는 뜻 → False
def has_cycle(head):

① cur.next — 다음 칸으로 갈 길을 잃기 전에 먼저 저장.
② prev — 화살표 방향을 뒤집는다.
③ nxt — 저장해둔 다음 칸으로 이동.

이번엔 이중 연결 리스트의 삽입/삭제를 완성해보자. 삭제는 노드 참조만으로 O(1)에 처리하는 것이 핵심이다.

# 알고리즘: 이중 연결 리스트 끝(tail)에 삽입
# 1) 새 노드를 만든다

# 알고리즘: 노드 참조만으로 O(1) 삭제
# 1) node의 "앞쪽" 링크를 정리한다
#    - 앞 노드가 있으면 그 노드의 next가 node.next를 가리키게 한다
#    - 앞 노드가 없으면(node가 head였다면) head를 node.next로 옮긴다
# 2) node의 "뒤쪽" 링크를 정리한다
#    - 뒤 노드가 있으면 그 노드의 prev가 node.prev를 가리키게 한다
#    - 뒤 노드가 없으면(node가 tail이었다면) tail을 node.prev로 옮긴다
def delete_node(self, node):
    if node.prev:
        node.prev.next = node.next
    else:
        self.head = node.next
    if node.next:

⑥ node.prev — 삭제되는 node의 다음 노드가, node를 건너뛰고 node의 앞 노드를 prev로 가리키게 한다.

마지막으로 원형 연결 리스트의 순회 종료 조건을 완성해보자.

# 알고리즘: 원형 연결 리스트 순회
# 1) head가 없으면 빈 리스트이므로 빈 결과를 반환한다
# 2) cur을 head로 두고, 일단 한 번은 무조건 진입하는 반복을 시작한다
#    2-1) cur의 데이터를 결과에 담는다
#    2-2) cur을 다음 노드로 이동한다
#    2-3) cur이 다시 head로 되돌아왔다면 한 바퀴를 다 돈 것이므로 종료한다

    if self.head is None:
        return []
    result, cur = [], self.head
    while True:
        result.append(cur.data)
        cur = cur.next

마지막으로 이중 연결 리스트 + 해시맵으로 LRU 캐시의 get/put을 완성해보자. _remove와 _add_front는 앞서 배운 O(1) 삭제·삽입을 그대로 재사용한 헬퍼 메서드다.

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = {}      # key -> Node, O(1) 조회용
        self.head = None     # 가장 최근 사용
        self.tail = None     # 가장 오래 사용 안 됨 → 다음 제거 대상

    # 알고리즘: 노드를 리스트에서 O(1)로 떼어내기 (양쪽 링크만 재배선)
    # 1) node의 이전 노드가 있으면 그 next를 node.next로 잇는다, 없으면 head를 node.next로 갱신한다
    # 2) node의 다음 노드가 있으면 그 prev를 node.prev로 잇는다, 없으면 tail을 node.prev로 갱신한다
    def _remove(self, node):        # 이전 주 delete_node와 동일한 O(1) 분리
        if node.prev: node.prev.next = node.next
        else: self.head = node.next
        if node.next: node.next.prev = node.prev
        else: self.tail = node.prev

    # 알고리즘: 노드를 리스트 맨 앞(head)에 O(1)로 삽입
    # 1) node의 prev는 None, next는 현재 head로 설정한다
    # 2) 기존 head가 있었다면 그 prev가 node를 가리키게 한다
    # 3) head를 node로 갱신한다
    # 4) 리스트가 비어 있었다면(tail이 None이면) tail도 node로 설정한다
    def _add_front(self, node):     # 항상 head 쪽이 "가장 최근"
        node.prev, node.next = None, self.head
        if self.head: self.head.prev = node
        self.head = node
        if self.tail is None: self.tail = node

    # 알고리즘: 조회 + "가장 최근 사용"으로 갱신
    # 1) key가 캐시에 없으면 -1을 반환한다
    # 2) 있으면 해시맵으로 해당 노드를 O(1)에 찾는다
    # 3) 그 노드를 리스트에서 떼어낸 뒤 다시 맨 앞에 붙여 "최근 사용"으로 표시한다
    # 4) 노드에 저장된 값을 반환한다
    def get(self, key):
        if key not in self.cache:
            return -1
        node = self.cache[key]
        self._remove(node)
        self.(node)   # 조회도 "사용"이므로 맨 앞으로 갱신
        return node.data

    # 알고리즘: 삽입/갱신 + 용량 초과 시 가장 오래된 항목 제거
    # 1) key가 이미 있으면 값만 갱신하고 맨 앞으로 옮긴 뒤 종료한다
    # 2) key가 없고 캐시가 가득 찼다면, tail(가장 오래 사용 안 됨)을 리스트와 해시맵에서 함께 제거한다
    # 3) 새 노드를 만들어 맨 앞에 추가하고 해시맵에도 등록한다
    def put(self, key, value):
        if key in self.cache:
            node = self.cache[key]
            node.data = value
            self._remove(node)
            self._add_front(node)
            return
        if len(self.cache) >= self.capacity:
            lru = self.        # 제거 대상 = 가장 오래 사용 안 된 노드
            self._remove(lru)
            del self.cache[lru.]  # 해시맵에서도 함께 삭제
        node = Node(value)
        node.key = key
        self._add_front(node)
        self.cache[] = node
⑧ _add_front — get()으로 값을 읽는 것도 "사용"이므로, 조회 직후 그 노드를 다시 맨 앞(head)으로 옮겨 최신 상태로 갱신해야 한다.
⑨ tail — 캐시가 가득 찼을 때 지워야 할 것은 가장 오래 사용되지 않은 노드, 즉 리스트의 tail이다.
⑩ key — 노드를 삭제하면서 해시맵에서도 같이 지우려면, 그 노드가 어떤 key에 대응하는지 노드 자신에 저장해둔 key가 필요하다.
⑪ key — 새로 만든 노드를 해시맵에 등록할 때 키는 매개변수로 받은 key 그대로다.

        if head is None:
            head = tail = node
        else:
            tail.next = node
            tail = node
    return head

def to_list(head):
    # 연결 리스트를 순회하며 파이썬 리스트로 바꾼다 (결과를 눈으로 비교하기 위함)
    result = []
    while head:
        result.append(head.data)
        head = head.next
    return result

def check(name, condition):
    # 조건이 참이면 PASS, 거짓이면 FAIL을 출력하고 통과 여부를 반환한다
    status = "PASS" if condition else "FAIL"
    print(f"[{status}] {name}")
    return condition

results = []

# ============================================================
# 1) reverse_list — next 필드를 다시 써서 방향을 뒤집는지 확인
# ============================================================
head = build_list([1, 2, 3, 4, 5])
results.append(check(
    "reverse_list: [1,2,3,4,5] -> [5,4,3,2,1]",
    to_list(reverse_list(head)) == [5, 4, 3, 2, 1]
))
results.append(check(
    "reverse_list: 노드 1개도 그대로 처리되는가",
    to_list(reverse_list(build_list([1]))) == [1]
))
results.append(check(
    "reverse_list: 빈 리스트(None)도 에러 없이 처리되는가",
    reverse_list(build_list([])) is None
))

# ============================================================
# 2) has_cycle — 토끼와 거북이가 순환을 정확히 감지하는지 확인
# ============================================================
a, b, c = Node('A'), Node('B'), Node('C')
a.next, b.next, c.next = b, c, None
results.append(check("has_cycle: 순환이 없는 리스트 -> False", has_cycle(a) is False))

a2, b2, c2 = Node('A'), Node('B'), Node('C')
a2.next, b2.next, c2.next = b2, c2, b2  # C가 다시 B를 가리켜 순환이 생김
results.append(check("has_cycle: 순환이 있는 리스트 -> True", has_cycle(a2) is True))

# ============================================================
# 3) DoublyLinkedList — append와 O(1) delete_node가 prev/next를
#    양쪽 다 올바르게 재배선하는지 확인
# ============================================================
dll = DoublyLinkedList()
for v in [1, 2, 3]:
    dll.append(v)
results.append(check("DLL append: head가 1인가", dll.head.data == 1))
results.append(check("DLL append: tail이 3인가", dll.tail.data == 3))
results.append(check("DLL append: 가운데 노드(2)의 prev가 1인가", dll.head.next.prev.data == 1))

target = dll.head.next  # 데이터가 2인 노드
dll.delete_node(target)
results.append(check("DLL delete_node: 삭제 후 head.next가 3인가", dll.head.next.data == 3))
results.append(check("DLL delete_node: 삭제 후 tail의 prev가 1인가", dll.tail.prev.data == 1))

# ============================================================
# 4) CircularLinkedList — tail.next가 다시 head를 가리키는지,
#    traverse가 한 바퀴만 돌고 멈추는지 확인
# ============================================================
cll = CircularLinkedList()
for v in ['A', 'B', 'C']:
    cll.append(v)
results.append(check("Circular append: tail.next가 head를 가리키는가", cll.tail.next is cll.head))
results.append(check("Circular traverse: [A,B,C] 순서로 순회되는가", cll.traverse() == ['A', 'B', 'C']))

# ============================================================
# 5) LRUCache — get으로 최근 사용 갱신, put으로 용량 초과 시
#    가장 오래된 항목이 제거되는지 확인
# ============================================================
cache = LRUCache(2)
cache.put(1, 'a')
cache.put(2, 'b')
results.append(check("LRUCache: get(1) == 'a'", cache.get(1) == 'a'))
cache.put(3, 'c')  # 용량 초과 -> 가장 오래 안 쓴 key=2가 제거되어야 함
results.append(check("LRUCache: 용량 초과 시 LRU(key=2) 제거", cache.get(2) == -1))
results.append(check("LRUCache: key=3은 살아있는가", cache.get(3) == 'c'))
results.append(check("LRUCache: get(1)을 다시 호출했으므로 key=1도 살아있는가", cache.get(1) == 'a'))

# ---- 결과 요약 ----
print("\n" + "=" * 40)
passed = sum(results)
print(f"결과: {passed} / {len(results)} 테스트 통과")
if passed == len(results):
    print("모든 테스트를 통과했습니다!")
else:
    print("실패한 항목의 코드를 다시 확인해보세요.")

참고: 테스트가 FAIL을 출력한다고 해서 코드 전체가 틀린 것은 아니다. 실패한 항목 하나하나가 "정확히 어떤 상황"에서 문제가 생기는지 알려주는 단서다. 예를 들어 reverse_list의 "노드 1개" 테스트만 실패했다면, 반복문에 들어가지 못하는 경계 조건(엣지 케이스)을 놓쳤을 가능성이 크다.

10 성취기준 자가진단

아래 항목을 스스로 점검해보자. 체크할 때마다 진행률이 채워진다.

  • prev, cur, nxt 세 포인터의 역할을 각각 설명할 수 있다.
  • 연결 리스트를 추가 메모리 없이 O(N)에 뒤집는 코드를 작성할 수 있다.
